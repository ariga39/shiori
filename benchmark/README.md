# Retrieval-Quality Benchmark (task #11, Phase 4C)

A baseline retrieval-quality benchmark for shiori hybrid search against a
versioned, fully synthetic corpus with explicit graded query judgments. This
benchmark does **not** tune the production ranking and does not modify any
task #10 E2E harness or product code.

## Frozen contract

- Model: `voyageai/voyage-4-nano`, pinned revision
  `67fabc9bef010dabc5f6024aa1b1b6b93410426f` (Apache-2.0, ~704 MB, multilingual,
  MRL dims 2048/1024/512/256).
- Generation is **local-only**: explicit commands; the model is never downloaded
  in CI, never accessed over the network by tests, and never committed.
- Embeddings: `encode_query` / `encode_document` with `truncate_dim=1024`,
  float32, L2 normalization. The 1024 dimension is an explicit fixed value. The
  HF model card documents an open-weight default of 2048 while the Voyage API
  docs list 1024 as the API default; this manifest records the choice as a
  deliberate fixed value, not a "default".
- Languages: en, zh, ja. en and zh are required; ja is included to form the
  three-language fixture. Cross-language directions en->zh and zh->en are
  required and bucketed separately. The report claims coverage of exactly
  en/zh/ja.
- Query classes (unchanged): exact, paraphrase, multilingual, temporal,
  multi_turn, duplicate, no_evidence.
- Metrics: Recall@5, MRR@10, nDCG@10, latency (cold and warm, p50/p95 with
  sample counts), and no-evidence behavior (false-return vs abstention).
- Voyage API is disabled; no private/API comparison in this phase.

## License and reproduction

- Corpus and judgments are explicit, versioned, human-reviewable JSONL
  fixtures. Relevance labels are hand-authored; no seed is used to derive
  content or labels.
- All synthetic content avoids the `tools/release_audit.py` patterns (email,
  private IP, host path, credential shapes).
- The manifest records model revision, file hashes, query/document prompt
  identity, dim/dtype/normalization, library and OS versions so results are
  reproducible.
- No model weights, caches, or generated vectors are committed. If vectors are
  later required as fixtures, a separate redistribution basis and size audit
  must be approved first.

## Layout

- `corpus_schema.json` — JSON schema for documents and judgments.
- `fixtures/corpus.jsonl` — synthetic documents (explicit).
- `fixtures/judgments.jsonl` — explicit query judgments.
- `requirements.in` — top-level benchmark constraints (input to the compile).
- `requirements.lock` — full transitive lock generated by `uv pip compile`
  (target python 3.13, platform aarch64-apple-darwin). Heavy local-only deps,
  installed in an isolated venv. NOT part of the wheel runtime surface.
- `query_rendering.py` — shared canonical-query renderer (generator + live
  harness use the same text, so vectors hash binds to both).
- `generate_vectors.py` — local-only embedding generation (pinned model).
- `run_benchmark.py` — retrieval harness, metrics, JSON/Markdown output.
- `manifest.json` — reproducibility manifest (committed).
- `results/*.json` — per-query and aggregate results (committed).
- `report.md` — baseline report (committed).
- `.generated/` — full vectors and local model outputs (ignored, not committed).

## Run (local only)

```bash
# 1. Install the exact transitive lock in an isolated venv (heavy, local-only)
uv venv .venv-benchmark && uv pip install -r benchmark/requirements.lock

# 2. Regenerate the lock (only when deliberately changing deps)
uv pip compile benchmark/requirements.in -o benchmark/requirements.lock \
  --python-version 3.13 --python-platform aarch64-apple-darwin

# 3. Generate vectors (downloads the pinned model once; ~704 MB cache)
#    Full vectors land in benchmark/.generated/ and are not committed.
.venv-benchmark/bin/python benchmark/generate_vectors.py \
  --fixtures benchmark/fixtures --out benchmark/.generated

# 4. Run the benchmark with a live model (phased cold/warm latency).
#    Live mode RE-ENCODES queries and ranks with the fresh embeddings (real
#    e2e), validates them against the pre-generated vectors (L2 tolerance),
#    and measures query-encode + retrieval + model-load phases. It never
#    overwrites vectors.json. `--emit-manifest` writes the committed manifest.
.venv-benchmark/bin/python benchmark/run_benchmark.py --live-model \
  --fixtures benchmark/fixtures --vectors benchmark/.generated/vectors.json \
  --out benchmark/results --report benchmark/report.md \
  --emit-manifest benchmark/results/manifest.json

# 5. Reproducibility test (CI-safe: no model, no network, small handcrafted data)
uv run pytest tests/test_benchmark_reproducibility.py
```

### Fresh-run note

The committed `manifest.json`/`results.json`/`report.md` bind the `.generated/`
vectors hash. Running the generator twice on the same machine produces the same
vectors hash (CPU float32, pinned lock). `--live-model` RE-ENCODES queries and
ranks with the fresh embeddings (the real e2e path), then validates them
against the pre-generated vectors (L2 tolerance); it never overwrites
`vectors.json`, so the committed manifest/results/report keep binding the same
pre-generated vectors hash.

To (re)produce the committed manifest without manual copy:

```bash
.venv-benchmark/bin/python benchmark/run_benchmark.py --live-model \
  --fixtures benchmark/fixtures --vectors benchmark/.generated/vectors.json \
  --out benchmark/results --report benchmark/report.md \
  --emit-manifest benchmark/results/manifest.json
```

### Determinism note

Vectors are generated on CPU with float32, L2 normalization, explicit 1024 dim,
and the exact compiled lock. Byte-identical hashes are guaranteed on the same
machine/hardware. Cross-hardware numeric variation is expected; the committed
hashes describe this machine run, not a cross-platform guarantee.

### Metrics (frozen)

- **Recall@5 / MRR@10**: treat grade>0 as relevant.
- **nDCG@10**: graded gain `2**grade - 1`, log2 discount (frozen definition).
- **no-evidence**: quality metrics are null/N/A and excluded from quality means
  and gap ranking; only false-return vs abstention is reported.
- **Latency**: `model_prefetch` (may include download when the cache is cold,
  separate), `model_load` (offline, `local_files_only=True`, download excluded),
  `cold/warm_query_encode`, `cold/warm_retrieval`, `cold/warm_e2e`; each with
  sample count + p50/p95. Model download is never mixed into retrieval latency.

### Canonical query rule (frozen)

- non-multi-turn: canonical query = whitespace-normalized `query_text`.
- multi-turn: canonical query = whitespace-normalized
  `conversation_context + current query`.
- The shared renderer (`query_rendering.py`) is used by the generator and the
  live harness; tests assert fixture `canonical_query` equals the renderer
  output.

## Gap ranking

The report lists, for each query class and language/direction bucket, the
supported findings and a data-supported gap ranking (which classes/directions
perform worst and what evidence supports that ordering).
